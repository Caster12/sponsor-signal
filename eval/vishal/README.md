# Vishal's postings (v001–v140)

| Path | What it holds |
| --- | --- |
| `labels/vishal.jsonl` | All 140 labels, one row per posting, in the five-field format. |
| `sources/urls.jsonl` | One row per posting: URL, employer, title, industry, location, capture method and provenance. The build reads this in place of `meta.jsonl`. |
| `sources/api/<id>.json` | The Greenhouse API response for each description-only posting, fetched October 21, 2026. |
| `texts/<id>.posting.txt` | The job description, for all 140. |
| `texts/<id>.raw.txt` | Everything on the page as captured, for full-page postings only (v001–v024). |
| `screenshots/<id>_extension.webp` | The extension's output next to the posting, where saved. |
| `postings.jsonl` | Generated by `npm run eval:build`. Do not edit by hand. |

## Two kinds of posting

- **v001–v024, full-page.** Captured from the live page in a browser; `raw.txt` is the page text and is checked against the page by SHA-256. Labeled blind by Vishal.
- **v025–v140, description-only.** Text from the Greenhouse public job-board API (`raw_page_status: "not_captured"` in `sources/urls.jsonl`), so there is no `raw.txt` and no screenshot. Labels were made by Vishal from the saved descriptions; AI was used only to format the files. Never substitute API descriptions for raw browser-page captures; capture the page before using one of these in the page-extraction evaluation.
